Manual das ferramentas

Como cada peça funciona por dentro

Sete ferramentas, uma seção cada: o que é, a mecânica, o código mínimo que funciona, e o que dá errado. As duas primeiras rodam aqui na página — abra no celular e teste, que é literalmente o passo 1 do plano.

01

Web Speech API — ouvir

Reconhecimento de fala embutido no Chrome. Você não instala nada, não paga nada e não gerencia modelo: o navegador captura o áudio, manda para o serviço de reconhecimento do Google e devolve texto. É o mesmo motor das legendas automáticas do YouTube.

Fale uma frase do dia a dia
O que o reconhecimento entender aparece aqui, com as alternativas e a confiança.
O código inteiro 
const SR = window.SpeechRecognition
        || window.webkitSpeechRecognition;

const rec = new SR();
rec.lang = 'pt-BR';
rec.continuous = false;     // para no fim da frase
rec.interimResults = true;  // texto parcial
rec.maxAlternatives = 3;     // 3 palpites, não 1

rec.onresult = (e) => {
  const rs = e.results;
  const r = rs[rs.length - 1];

  const texto = r[0].transcript;
  const conf  = r[0].confidence;  // 0 a 1

  if (r.isFinal) processar(texto, conf);
};

rec.onerror = (e) => tratar(e.error);
rec.onend   = ()  => resetarBotao();

rec.start();

O que dá errado

  • Só funciona em HTTPS ou localhost. Em HTTP o objeto existe mas nunca dispara resultado.
  • Precisa de rede. É reconhecimento no servidor, não no aparelho — sem internet, não ouve.
  • continuous: true é instável no Android: para sozinho depois de alguns segundos. Use false e uma gravação por vez.
  • Firefox não suporta. Safari só a partir do iOS 14.5, com prefixo.
  • O áudio vai para servidores do Google. Para um público que vai falar da própria vida, isso precisa estar no seu aviso de privacidade.
  • onend dispara sempre — inclusive depois de erro. É onde você reseta a interface, não no onresult.

O truque que vale ouro aqui

  • maxAlternatives = 3 devolve os três melhores palpites. Mande os três para o Claude e deixe ele escolher qual faz sentido na frase — “cus cus”, “cuscuz”, “cuz cuz” viram CUSCUZ. É a defesa mais barata que existe contra erro de sotaque.
02

speechSynthesis — falar

A síntese de voz do sistema. Diferente do reconhecimento, roda inteiramente no aparelho: funciona offline, é instantânea e não manda nada para lugar nenhum. Toda a interface falada do app sai daqui.

Ajuste a velocidade para 0.85–0.95 — adulto em alfabetização precisa de tempo para acompanhar.
O código inteiro 
function falar(texto) {
  speechSynthesis.cancel();  // senão enfileira

  const u = new SpeechSynthesisUtterance(texto);
  u.lang   = 'pt-BR';
  u.rate   = 0.9;   // mais devagar que o padrão
  u.pitch  = 1;
  u.volume = 1;

  // escolhe uma voz pt-BR se houver
  const v = speechSynthesis.getVoices()
    .find(v => v.lang.startsWith('pt'));
  if (v) u.voice = v;

  u.onend = () => liberarBotaoDeFalar();
  speechSynthesis.speak(u);
}

O que dá errado

  • getVoices() volta vazio na primeira chamada. As vozes carregam de forma assíncrona — espere o evento voiceschanged antes de escolher.
  • iOS exige um toque do usuário antes do primeiro speak(). Um áudio automático ao abrir a página simplesmente não sai.
  • Sem cancel() antes, as falas empilham e a pessoa ouve tudo em sequência.
  • A qualidade da voz varia por aparelho. Android barato costuma ter voz pt-BR robótica, mas inteligível — teste no aparelho real, não no seu.
  • No Chrome desktop a fala corta perto dos 15 segundos. Frases curtas resolvem, e no app elas já são curtas.

A economia escondida. Como a síntese é local e gratuita, você pode falar tudo: cada botão, cada instrução, cada erro. Isso é o que torna o app usável por quem não lê — e é justamente o que seria proibitivo se você pagasse por caractere sintetizado.

03

PWA — virar app sem loja

Um PWA é o seu site mais dois arquivos. Com eles o Chrome oferece “adicionar à tela inicial”, e a partir daí o site abre em janela própria, com ícone, sem barra de endereço — indistinguível de um app instalado, para quem usa.

manifest.json 
{
  "name": "Palavra",
  "short_name": "Palavra",
  "start_url": "/",
  "display": "standalone",
  "background_color": "#0E131C",
  "theme_color": "#1B3A6B",
  "icons": [
    { "src": "/icon-192.png",
      "sizes": "192x192",
      "type": "image/png" },
    { "src": "/icon-512.png",
      "sizes": "512x512",
      "type": "image/png" }
  ]
}
no index.html 
<link rel="manifest" href="/manifest.json">
<meta name="theme-color" content="#1B3A6B">
<meta name="viewport"
      content="width=device-width,initial-scale=1">

O que o Chrome exige para oferecer a instalação

  • Servido por HTTPS
  • Manifesto válido com name, start_url, display e ícones de 192px e 512px
  • Um service worker registrado que trate o evento fetch

O que dá errado

  • Sem os dois tamanhos de ícone, o prompt de instalação não aparece — e não há mensagem de erro dizendo isso.
  • O usuário do seu público não vai achar “adicionar à tela inicial” sozinho no menu. Faça um botão na tela que dispare o evento beforeinstallprompt capturado, com áudio explicando.
  • No iOS a instalação é manual pelo Safari (Compartilhar → Adicionar à Tela de Início) e o service worker tem limites. Se seu público é Android, ignore; se não, teste.
04

Service worker — funcionar sem internet

É um script que roda numa thread separada e fica entre a sua página e a rede, como um proxy que você programa. Toda requisição passa por ele, e ele decide: devolvo do cache, busco na rede, ou tento a rede e caio no cache se falhar.

  1. install — dispara uma vez, na primeira visita. É onde você baixa e guarda os arquivos do app.
  2. activate — assume o controle. É onde você apaga caches de versões antigas.
  3. fetch — dispara em toda requisição, para sempre. É onde mora a estratégia de cache.
sw.js 
const CACHE = 'palavra-v1';
const ASSETS = [
  '/', '/index.html', '/app.js',
  '/estilo.css', '/wordlist.json'
];

self.addEventListener('install', e => {
  e.waitUntil(
    caches.open(CACHE).then(c => c.addAll(ASSETS))
  );
  self.skipWaiting();
});

self.addEventListener('activate', e => {
  e.waitUntil(
    caches.keys().then(ks => Promise.all(
      ks.filter(k => k !== CACHE)
        .map(k => caches.delete(k))
    ))
  );
  self.clients.claim();
});

self.addEventListener('fetch', e => {
  // nunca cacheie a chamada ao LLM
  if (e.request.url.includes('/api/')) return;

  e.respondWith(
    caches.match(e.request)
      .then(r => r || fetch(e.request))
  );
});
registro, no app.js 
if ('serviceWorker' in navigator) {
  navigator.serviceWorker.register('/sw.js');
}

O que dá errado

  • Sem skipWaiting() + clients.claim(), a versão antiga continua no comando até todas as abas fecharem. Você publica a correção e jura que não subiu.
  • Cache API não é localStorage. São dois armazenamentos diferentes, com APIs diferentes.
  • Cachear a chamada da API do LLM devolve a resposta da sessão anterior. Exclua a rota /api/ explicitamente.
  • Trocar o nome do cache (v1 → v2) é o que força a atualização. Sem isso, os arquivos velhos ficam.
  • O service worker não enxerga o DOM. Ele é rede e cache, mais nada.
05

localStorage — guardar o progresso

Um dicionário de texto que sobrevive ao fechar o app, dentro do próprio celular. Para o seu caso substitui banco de dados, login e servidor inteiros.

o estado do aluno inteiro 
const CHAVE = 'palavra.aluno';

const vazio = {
  familias: {},     // { t: 0.9, l: 0.7, j: 0.3 }
  palavras: [],     // geradoras já trabalhadas
  descobertas: [],  // palavras que ela formou
  sessoes: 0,
  estagio: 1         // 1 a 5, a grade fonética
};

function carregar() {
  try {
    const cru = localStorage.getItem(CHAVE);
    return { ...vazio, ...JSON.parse(cru || '{}') };
  } catch {
    return { ...vazio };  // JSON corrompido
  }
}

function salvar(estado) {
  localStorage.setItem(CHAVE, JSON.stringify(estado));
}

O que dá errado

  • Guarda só texto. Objeto tem que passar por JSON.stringify na ida e JSON.parse na volta — e o parse precisa de try/catch, senão um dado corrompido derruba o app na abertura.
  • Se a pessoa limpar os dados do site, o progresso vai junto. Para um protótipo é aceitável; quando doer, sincronize com um Supabase.
  • É síncrono, então trava a thread enquanto escreve. Com um objeto pequeno como esse, irrelevante.
  • É por origem e por navegador. Trocar de celular começa do zero.

Note o { ...vazio, ...salvo }: quando você adicionar um campo novo ao estado numa versão futura, os alunos que já têm dado salvo recebem o valor padrão em vez de undefined. É uma linha que evita uma classe inteira de bug.

06

Cloudflare Worker — o proxy da chave

Qualquer pessoa lê o código-fonte do seu app. Se a chave da API estiver lá, ela é copiada e a conta é sua. O Worker é uma função que roda no servidor, guarda a chave e repassa a chamada — a única parte do sistema que não vive no celular.

worker.js — completo 
const API = 'https://api.anthropic.com/v1/messages';
const APP = 'https://seu-app.pages.dev';

const cors = {
  'Access-Control-Allow-Origin': APP,
  'Access-Control-Allow-Headers': 'content-type'
};

export default {
  async fetch(req, env) {

    // sondagem que o navegador manda antes do POST
    if (req.method === 'OPTIONS')
      return new Response(null, { headers: cors });

    if (req.method !== 'POST')
      return new Response('só POST', { status: 405 });

    const { fala, estado } = await req.json();

    const r = await fetch(API, {
      method: 'POST',
      headers: {
        'content-type': 'application/json',
        'x-api-key': env.ANTHROPIC_API_KEY,
        'anthropic-version': '2023-06-01'
      },
      body: JSON.stringify({
        model: 'claude-sonnet-5',
        max_tokens: 2000,
        system: [{
          type: 'text',
          text: PROMPT_FREIRIANO,
          cache_control: { type: 'ephemeral' }
        }],
        output_config: {
          format: {
            type: 'json_schema',
            schema: SCHEMA
          }
        },
        messages: [{
          role: 'user',
          content: `Fala: ${fala}\nEstado: ${estado}`
        }]
      })
    });

    return new Response(r.body, {
      headers: {
        ...cors,
        'content-type': 'application/json'
      }
    });
  }
};
publicar 
npm i -g wrangler
wrangler login
wrangler secret put ANTHROPIC_API_KEY
wrangler deploy

O que dá errado

  • Sem os cabeçalhos de CORS, o navegador bloqueia a resposta e o erro no console não diz que o problema é CORS de forma óbvia.
  • Esquecer o OPTIONS: o navegador manda uma requisição de sondagem antes do POST, e se ela falhar o POST nem sai.
  • Access-Control-Allow-Origin: * deixa qualquer site usar seu Worker — e sua cota. Fixe no domínio do seu app.
  • A chave vai por wrangler secret, nunca no código nem no wrangler.toml.
  • Free tier: 100 mil requisições por dia. Com 20 alunos você usa 400 por mês.
07

A chamada ao Claude

Três recursos fazem o trabalho pesado aqui: saída estruturada para você receber objeto em vez de texto, cache de prompt para o custo não escalar com o tamanho das instruções, e uma única chamada por turno resolvendo tudo.

o schema — o contrato da resposta 
const SCHEMA = {
  type: 'object',
  properties: {
    transcricao_corrigida: { type: 'string' },
    palavra_geradora:      { type: 'string' },
    por_que_essa:          { type: 'string' },
    carga_existencial:     { type: 'number' },
    perguntas_debate: {
      type: 'array',
      items: { type: 'string' }
    },
    proxima_pergunta:      { type: 'string' }
  },
  required: [
    'transcricao_corrigida', 'palavra_geradora',
    'por_que_essa', 'carga_existencial',
    'perguntas_debate', 'proxima_pergunta'
  ],
  additionalProperties: false
};

Por que cada peça está aí

RecursoO que resolve
output_config
.format		 Você recebe JSON validado contra o schema. Sem regex, sem “às vezes ele responde com markdown em volta”.
cache_control Seu prompt pedagógico pode ter 3 mil tokens explicando o método. Cacheado, custa 10% a partir da segunda chamada.
max_tokens Teto rígido da resposta. Se estourar, vem cortada — deixe folga.
additional
Properties		 Precisa ser false, e todo campo listado em required. É exigência do schema estrito.

Uma chamada por turno, não quatro. Corrigir a transcrição, escolher a palavra, justificar a escolha, gerar as perguntas de debate e formular a próxima pergunta são cinco tarefas — mas cabem num pedido só, porque todas olham para a mesma frase. Cinco chamadas custariam cinco vezes mais e demorariam cinco vezes mais, sem ficar melhores.

08

As sete peças em um turno

Onde cada ferramenta entra, do momento em que a pessoa abre o app até ela descobrir uma palavra nova.

  1. Service worker serve o app do cache — abre instantâneo, mesmo com wifi ruim.
  2. localStorage devolve o estado: quais famílias silábicas ela já domina.
  3. speechSynthesis faz a pergunta em voz alta.
  4. Web Speech API ouve a resposta e devolve 3 alternativas com confiança.
  5. Cloudflare Worker recebe as alternativas + o estado e chama o Claude com a chave protegida.
  6. Claude devolve JSON: transcrição corrigida, palavra geradora, perguntas de debate.
  7. speechSynthesis confirma em voz: “ouvi CUSCUZ, tá certo?” — e só prossegue com o sim.
  8. Seu código silabifica, gera as famílias, monta a ficha da descoberta.
  9. localStorage grava o que mudou. Fim do turno.

Só o passo 5 custa dinheiro e só os passos 4 e 5 precisam de internet. Todo o resto funciona com o celular no modo avião — inclusive a ficha da descoberta, que é onde a pessoa passa a maior parte do tempo.

As demos de reconhecimento e síntese usam as APIs reais do seu navegador, sem nenhuma biblioteca. Se funcionarem no celular do aluno, funcionam no app — é exatamente o mesmo código que está mostrado aqui.
